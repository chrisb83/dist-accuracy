## Cross-cutting issues

**1. The tail is built by subtraction instead of a complementary form - 12 of
16 distributions, plus a milder form in two more (`arcsine`, `bradford`);
only `cauchy` and `cosine` are clean.** This is the most consistent result of the review, and
the cheapest to fix: every distribution reviewed either implements `sf`/`logsf`
subtractively or inherits the generic versions, and in every case they collapse
in the right tail where a closed form exists.
- `fisk` F1: `_sf`/`_logsf` are `log1p(-cdf)`-shaped with `cdf -> 1`, so `sf`
  returns exactly `0.0` and `logsf` `-inf` for all `x > exp(36.7/c)`, with up
  to 5.0e14 ulp just before the cliff - although `sf = 1/(1 + x^c)` is exact.
- `mielke`: all four of `sf`, `logsf`, `logcdf`, `isf` are inherited and each
  fails at its demonstration point.
- `kappa4`: `sf(40, 0, 0) = 0.0` vs 4.25e-18, `logsf = -inf` vs -40,
  `isf(1e-300, 0, 0) = inf` vs 690.78.
- `gamma`: `logcdf`/`logsf` are not implemented at all; the generic
  `log(cdf)` / `log(sf)` underflows to `-inf` where the true log-probability is
  an ordinary number.
- `alpha`: `sf`, `logsf`, `logcdf`, `isf` are all inherited and all fail:
  `sf(1e17, 3.57) = 0.0` vs 6.8e-21, `logsf = -inf` vs -46.4,
  `logcdf(0.01, 3.57) = -inf` vs -4654.8, and `isf(1e-20, 3.57)` returns a
  *negative* number (-1.6e13 vs 6.8e16), because `ppf(1 - q)` takes the
  reciprocal of a rounding error.
- `anglit`: implements `sf` correctly but inherits `isf = ppf(1 - q)`:
  `isf(1e-18)` is off by 5.7e6 ulp, while `pi/4 - arcsin(sqrt(q))` is exact.
- `beta`: implements `sf`/`isf` properly (`betaincc`/`betainccinv`) but
  inherits `logcdf`/`logsf`, which underflow to `-inf` exactly as in `gamma`:
  `logcdf(1e-200, 3, 2) = -inf` vs -1380.16, `logsf(0.9, 1000, 1000) = -inf`
  vs -1026.15. A log-space `ibeta` prefix (`a log x + b log1p(-x) - betaln`)
  fixes both.
- `dgamma`: implements `sf`/`isf` via `gammaincc`/`gammainccinv` but inherits
  `logcdf`/`logsf`, which underflow as in `gamma`: `logcdf(-1000, 1.10233)` =
  `logsf(1000, 1.10233)` = -inf vs -999.94. `log(0.5) + log Q(a, |x|)` with a
  log-space `igamc` fixes both.
- `cosine` (clean): implements `sf`/`isf` through `scu._cosine_cdf`/`_invcdf`,
  and the inherited `logcdf`/`logsf` (median switch) measure 1.09 ulp.
- `betaprime`: implements `sf` properly but inherits `isf = ppf(1 - q)`,
  `logcdf` and `logsf`: `isf(1e-20, 5, 6) = inf` vs 5250.97,
  `logsf(1e70, 5, 6) = -inf` vs -961.74, `logcdf(1e-70, 5, 6) = -inf` vs
  -800.38 - the same `-inf` underflow as `gamma` and `beta`.
- `burr12` F2/F4: implements every method, but `_logcdf` is
  `log1p(-(1 + x**c)**(-d))` - log1p of minus the sf - so it returns `-inf`
  once `d*x**c < eps` in the left tail of every parameter set
  (`logcdf(1e-10, 10, 4)`; -inf vs -228.87) and loses up to 1.5e12 ulp for
  large d. The other three log/complement methods are written correctly.
- `chi`, `chi2`: implement `sf` via `gammaincc`/`chdtrc` but inherit
  `logcdf`/`logsf`, which return `-inf` in the tails exactly as in `gamma`
  (`chi.logsf(60, 78)`, `chi.logcdf(1e-10, 78)`, `chi2.logsf(4000, 2)` = -inf
  vs -2000).
- `arcsine` (milder): inherited `sf = 1 - cdf` reaches 1.9e15 ulp at
  x = 1 - 1.1e-16. The tool rates it within conditioning (the input rounding
  of x near 1), but `2/pi*arcsin(sqrt(1 - x))` gives < 1 ulp for exact inputs.
- `bradford` (milder): inherited `sf`, `logsf`, `isf` stay within
  conditioning (`sf(1 - 1e-12, 1)`: 5.7e11 ulp at cond 1.0e12); closed forms
  are listed but gain little.
- `weibull_max`: inherits `logsf = log(sf)` and `isf = ppf(1 - q)`:
  `logsf(-1e-200, 2) = -inf` vs -921.07, `isf(1e-20, 2) = 0.0` vs -1e-10.
  `weibull_min` implements all of these and is clean here.
- `dweibull`: inherits `logcdf`/`logsf`, which return `-inf` once
  `|x|**c >~ 745` (`logcdf(-30, 2)` = `logsf(30, 2)` = -inf vs -900.69);
  `-log(2) - |x|**c` on the tail side is exact.
- **Exponential family (run 2026-10-29):** all three inherit `logcdf`/`logsf`
  and all three return `-inf` in the tails: `exponnorm.logcdf(-40, 1.5)`,
  `exponnorm.logsf(2000, 1.5)`, `exponpow.logsf(3, 2.697)`,
  `exponpow.logcdf(1e-200, 2)`, and exponweib's wherever cdf/sf underflow.
  `exponnorm` also inherits `isf = ppf(1 - q)`: `isf(1e-20, 1.5)` = 100.0 vs
  69.41. `exponweib` F1 (loss) is the subtractive tail in another form:
  `sf = -_pow1pm1(log1p(-exp(-x**c)), a)` rounds `exp(-x**c)` to 1 first, so
  `sf = 1.0` for every x < 1e-16 at a = 0.01 (truth 0.32-0.999); passing
  `-expm1(-x**c)` instead fixes it.
- **fatiguelife / foldcauchy (run 2026-10-29):** `fatiguelife` inherits
  `logcdf`/`logsf`, which go to `-inf` in the tails although
  `sc.log_ndtr(±z)` gives them exactly (Opportunities). `foldcauchy`
  implements an accurate `sf` but inherits `isf = ppf(1 - q)`:
  `isf(1e-20, 1)` = 1e16 vs 6.4e19; a closed form via `cot(pi q)` is in the
  report.
- **f / foldnorm (run 2026-10-29):** `f` implements `sf` via `fdtrc` but
  inherits `logcdf`, `logsf` and `isf = ppf(1 - q)`: `logcdf(1e-30, 29, 18)`
  = -inf vs -981.8, `logsf(1e100, 29, 18)` = -inf vs -2063.2,
  `isf(1e-20, 29, 18)` = inf vs 455.85 (`betaincinv` on the complement fixes
  it). `foldnorm` has an accurate `sf` but inherits `logpdf`, `logcdf`,
  `logsf` and `isf`, which go to `-inf`/lose the tail (`isf(1e-20, 1)` = 10.0
  vs 10.26); log-space forms via `log_ndtr` are in the report.
- **genlogistic / logistic (run 2026-10-29):** `genlogistic` inherits
  `logsf = log(sf)` and implements `isf` as `ppf(1 - q)` (F5, loss, verified):
  `isf(1e-17, c)` = inf vs 39.14, severe already for q <= 1e-8;
  `logsf(800, 1)` = -inf vs about -800 (fix: `log1mexp(logcdf)` with a
  right-tail form). Its `sf = -expm1(logcdf)` is complementary but inherits
  the F1 overflow (see 3). `logistic` is clean on all eight methods
  (`expit`/`log_expit`/`logit`, at most 1.12 ulp), making it the third clean
  distribution after `cauchy` and `cosine`.
- **genexpon (run 2026-10-29):** inherits `logsf = log(sf)`, which is `-inf`
  once (a+b)x >~ 745 (`logsf(1000, 1, 1, 1)` = -inf vs -1999.0), although
  logsf is just the exponent `-a*x - (b/c)*(c*x + expm1(-c*x))`. `genpareto`
  implements `logsf` (and its inherited `logcdf` is fine in the right tail).
- **genextreme / gengamma (run 2026-10-29):** `genextreme` inherits
  `logsf = log(sf)`, -inf in the right tail (`logsf(800, 0)` vs -800);
  `gengamma` inherits both `logcdf` and `logsf` (opportunities only).
- **genhalflogistic / gompertz (run 2026-10-29):** `genhalflogistic`
  implements only pdf/cdf/ppf, so sf = `1 - cdf`, isf = `ppf(1 - q)`, logsf,
  logpdf and logcdf are all generic (opportunities, each with a demonstration
  point). `gompertz` inherits `logsf = log(sf)`, -inf for `logsf(10, 1)`
  although it is exactly `-c*expm1(x)`.
- **halflogistic / halfnorm (run 2026-10-30):** both implement `sf` correctly
  but inherit `logsf`, which above the median is `log(sf)` and underflows:
  `halflogistic.logsf(800)` = -inf vs -799.31 (fix `log(2) + log_expit(-x)`),
  `halfnorm.logsf(40)` = -inf vs -803.92 (fix `log(2) + log_ndtr(-x)`).
  Opportunities only; inherited logcdf is accurate in both.
- **gausshyper / hypsecant (run 2026-10-30):** `gausshyper` implements only
  `pdf`, so cdf/ppf are generic quadrature/root-finding and sf = `1 - cdf`,
  isf = `ppf(1 - q)`, logsf and logcdf all reach loss at their demonstration
  points (opportunities; the exact reflection 1 - X ~ gausshyper(b, a, c,
  -z/(1+z)) gives a complementary form). `hypsecant` implements sf/isf but
  inherits logpdf/logcdf/logsf, all -inf past |x| ~ 708 (`logpdf(800)`,
  `logcdf(-800)`, `logsf(800)` vs -800.45; closed forms in the report).
- **invgamma / invgauss (2026-10-30, verified):** `invgamma` inherits
  `logcdf`/`logsf` (`logsf(1e80, 4.07)` = -inf vs -752.4; opportunity).
  `invgauss` F1 (loss) is a log-space version of the same subtraction: `logsf`/
  `sf` are `a + log1p(-exp(b - a))` with `a = log_ndtr(z1)` and
  `b = 2/mu + log_ndtr(-z2)`, which cancels whenever sf << Phi(-z1). That
  happens in the right tail (about x/mu ulp; `sf(1e9, 1e3)` 5e7 ulp) and on all
  of x < mu**2 for large mu (`sf(1e40, 1e20)` = 0, logcdf > 0). `wald` is
  `invgauss` at mu = 1 and inherits it.
- **geninvgauss / invweibull / jf_skew_t / johnsonsb / johnsonsu / landau /
  norminvgauss (2026-10-30):** all seven inherit `logcdf`/`logsf` (and all
  but geninvgauss `logpdf`) and return `-inf` once the base method
  underflows: `invweibull` (all three, both tails), `johnsonsb`/`johnsonsu`
  (beyond |z| ~ 38; `log_ndtr` forms exist), `landau` (`logpdf(-5.2)` = -inf
  vs -823.08, `logcdf(-5.2)` vs -830.25). `geninvgauss` also inherits
  `sf = 1 - cdf`. Listed as opportunities, not findings.
- **laplace_asymmetric / levy_l (2026-10-30, verified 4/4 and 3/3):**
  implemented tails built by subtraction. `laplace_asymmetric` F1/F2: `cdf =
  1 - exp(-x*kappa)/(1+kappa**2)` (x >= 0) cancels for small kappa, `sf`
  mirrors it for large kappa (`cdf(1e-300, 1e-150)` = 0.0; 5e14 ulp at
  kappa = 1e-8); fix with `-expm1(-x*kappa)` plus the kappa-weighted terms.
  `levy_l` F1: `cdf = 2*_norm_cdf(1/sqrt(|x|)) - 1` cancels as x -> -inf (0.0
  for x <= -1e32 vs 8e-17; 3.3e9 ulp at -1e20); fix `erf(1/sqrt(2|x|))`.
  `levy` computes the same quantity with `erfc` and is clean.
- **laplace / levy / laplace_asymmetric / levy_l (2026-10-30):** all four
  inherit `logcdf`/`logsf` (and all but `laplace_asymmetric` `logpdf`) and
  return `-inf` in the tails: `laplace` beyond |x| ~ 708 (`logpdf(-800)` vs
  -800.69), `levy` `logpdf`/`logcdf` for x < ~7e-4, `levy_l` `logpdf`/`logsf`
  near 0-. Opportunities, not findings.
- **gibrat / kappa3 / loggamma / loglaplace / maxwell / moyal (2026-10-30):**
  all inherit `logcdf`/`logsf` (`loglaplace`, `kappa3`, `moyal` also
  `logpdf`) and return `-inf` in a tail: `gibrat` once `ndtr` underflows
  (x < ~1e-17 or > ~1e17; `sc.log_ndtr(+-log x)` fixes both), `loglaplace`
  (`logcdf(1e-300, 3)` = -inf vs -2073.02), `maxwell` (`logsf(40)`,
  `logcdf(1e-110)`), `moyal` (logpdf/logcdf for x < ~-7.3, logsf for
  x > ~1416). `moyal` also inherits `isf = ppf(1 - q)`, which is inf for
  q < 1.1e-16 (`-2*log(erfinv(q)) - log 2` avoids it). `kappa3`'s inherited
  `logsf(1e200, 2)` = 0.0 vs -921 follows from its F1. `lognorm` implements
  all four log methods via `log_ndtr` and has none of these. Opportunities,
  not findings.
SciPy tracks the pattern generically in #17832 (open) and #11465 (closed via
PR #21050) without having fixed it for any of these. One
`_sf`/`_logsf`/`_logcdf`/`_isf` override per distribution removes the class,
and the reports give closed forms under "Opportunities".

**2. An intermediate is formed explicitly and overflows (or underflows),
although the result is a representable double - 9 of 16.** The same bug written five different ways
(`beta` F2 is the fifth: Boost `ibeta_derivative` overflows on
`1/(x*(1-x))` for x <~ 1e-308, and SciPy turns that into a Python
`OverflowError` - `beta.pdf` *raises* where the true pdf is 1.2e155; see 8):
- `alpha` F1, via the **shared helper `_norm_logpdf`** (`-x**2 / 2.0`,
  `_continuous_distns.py` line 367): `x**2` overflows for
  1.34e154 < |x| < 1.9e154, where `-x**2/2` is still finite, so
  `alpha.logpdf` returns `-inf` for x in about [5.3e-155, 7.5e-155] at any a.
  The helper is called 8 times in `_continuous_distns.py`; `norm.logpdf(1.5e154)`
  returns `-inf` where the truth is -1.125e308 (computed by hand, not run
  through the harness). `-(x/2)*x` or `-0.5*x*x` ordering avoids it.
- `fisk` F2/F3: `x**(-c-1)`, `x**(-c)` overflow for `x < exp(-709.8/(c+1))`, so
  `pdf` returns `nan`/`inf` and `logpdf`/`logcdf` `-inf`
  (`pdf(1e-300, 2)` = `nan`, truth 2e-300).
- `mielke` F1/F2/F3: the mirror image - `x**k` and `(1+x**s)**(1+k/s)` overflow
  in the *right* tail, so `cdf(1e10, 1e6, 1.0)` = `nan` (truth 0.9999) and
  `cdf(2.0, 1000, 1.0)` = `0.0` (truth 8.1e-177).
- `kappa4` F1/F5: `y = (1 - k x)**(1/k)` (or `exp(-x)` at k = 0) overflows for
  h < 0, and `q**h` for `|h| >~ 1e3`; `cdf(-700, -1e6, 0)` = `0.0` where the
  truth is 0.9993 at a conditioning of 7.0e-4 - a well-conditioned point in the
  *bulk* returning a completely wrong value, not a tail artefact.
- `burr12` F1/F3: `x**c` overflows once `c*log(x) > 709.8`, so `logpdf`
  and `logsf` return `-inf` even at the inventory example

-5.77e-311. **Correction from `exponnorm` (2026-10-29, verified):

**9. A closed form written as a sum of nearly opposite terms (3 of 4 in the
2026-10-29 runs: fatiguelife, foldcauchy, foldnorm).** Both formulas are exact but cancel
on one side of the distribution; an algebraically equivalent form removes it.
- `foldcauchy` F1 (loss, verified): `cdf = (arctan(x-c) + arctan(x+c))/pi`
  cancels for x << max(1, c): `cdf(1e-20, 1)` = 0.0 vs 3.18e-21,
  `cdf(10, 1e6)` off by 3.7e8 ulp, and cdf = 0.0 for all x < c at c = 1e100.
  `arctan2(2x, 1 + (c-x)(c+x))/pi` measured at most 1.2 ulp (needs scaling
  above ~1e154). The generic ppf and logcdf inherit it.
- `fatiguelife` F1 (loss, verified): `ppf`/`isf` use
  `tmp + sqrt(tmp**2 + 4)` with tmp = c*ndtri(q), which cancels for q < 0.5
  (ppf) and q > 0.5 (isf): 484 ulp already at c = 29, q = 0.01; 3.2e11 ulp at
  c = 1e6; 0.0 once c|ndtri(q)| > ~1e8. Fix: `4/(hypot(tmp, 2) - tmp)**2`.
- `fatiguelife` F4 (severe in cdf, loss in sf, verified) is a related
  rounding: `sqrt(x) - 1/sqrt(x)` is 0 at x = 1 + 2**-52, so cdf = sf = 0.5
  for c < ~1e-16; `(x-1)/(c*sqrt(x))` fixes it.
- `foldnorm` F1/F2 (loss, verified 2/2) is the normal-distribution twin of
  `foldcauchy` F1: `cdf = (erf((x-c)/√2) + erf((x+c)/√2))/2` (line 2703)
  cancels for x << 1/c (`cdf(1e-20, 1.95)` = 0.0 vs 1.19e-21) and, because
  it uses `erf` instead of `erfc`/`ndtr`, left of the mode once x - c < ~-5
  (0.0 below ~-8.3; `cdf(1, 30)` = 0.0 vs 3.3e-185). The formula was
  introduced by PR #18207 (1.11) to improve the left tail. The generic ppf
  inherits both (`ppf(1e-20, 1.95)` = 0.0). Both "folded" distributions need
  the same kind of rewrite, e.g. `ndtr(x-c) - ndtr(-x-c)` with an
  `erf`-difference series for small x.

**11. `scipy.special.inv_boxcox1p` returns `x` when `|lmbda*x| < 1e-154`
(new 2026-10-29, from `genpareto` F1, verified).** It uses
`(1 + lmbda*x)**(1/lmbda) - 1 ~ x`, which only holds if x itself is small;
the lmbda -> 0 limit is `expm1(x)`. So `genpareto.cdf(x, c)` = x for every
|c| < ~2.5e-139: `cdf(2, 1e-300)` = 2.0 (truth 0.865), above 1 for any
x > 1, and the inherited `logcdf` below the median inherits it
(`logcdf(0.5, 1e-200)` = -0.693 vs -0.933). Another exception to 6.
`inv_boxcox`, `boxcox` and `boxcox1p` are accurate in the same regime.
`genpareto._cdf` (line 3227) is the only `inv_boxcox1p` call in
`scipy.stats`, but the function is public, so it should be reported in
`scipy.special`. No SciPy issue found (searched "inv_boxcox1p"; #25190 only
renames it).
Related `genexpon` (2026-10-29, verified 5/5) defects belong to existing
patterns, all in the regime c*x << 1:
- Pattern 9 (opposite terms): F1/F2 (loss) - `ppf`/`isf` are
  `(t + lambertw(-b/s*exp(-t)).real)/c`, where t and W are both ~b/s and their
  sum is c*x. `ppf(1e-20, 1, 1, 1)` = -1.1e-16 (truth 1e-20), ppf is pure
  noise in the low tail of every parameter set, isf is 0 or negative as
  q -> 1, and 3.5e6 ulp in the bulk at (1000, 10000, 0.1). `sc.lambertw` itself
  is accurate. Fix: solve a*y + b*(y + expm1(-y)) = -c*log1p(-p) for y = c*x
  (series for `y + expm1(-y)`), Lambert W as the Newton starting point.
- Pattern 5 (cancelling exponent): F4 (severe) - `-(a+b)*x` and
  `b*(-expm1(-c*x))/c` cancel to ~ -a*x for a << b (cdf 9.1e6 ulp at
  a/b = 1e-7), and F5 (moderate, pdf/sf 2.6e3 ulp) is the same E inside exp.
  `-a*x - (b/c)*(c*x + expm1(-c*x))` is free of it.
- Pattern 2 in log form: F3 (loss) - `_logpdf` uses `np.log(a + b*u)`, which

  sign (`logpdf(1e-10, 1, 1, 1)` = +8.3e-18 vs -1.5e-20). Fix:
  `log(a) + log1p(b*u/a)`.
`genpareto` also adds F4 (loss, cond 5e15) to the rounded-endpoint family
below (`c*x` rounds to -1 at x = -1/c, so logpdf/logsf = -inf exactly at
`support()[1]`) and F5 (minor, 519 ulp, exp of a large rounded log) to 4.

**Two defects that are NOT cross-cutting, and should not be mistaken for it:**
- `mielke` F1 (the `cdf` collapse) has **no** burr/fisk counterpart. The
  verifier confirmed `burr_gen._cdf` (line 1218) already uses the bounded
  `(1 + x**-c)**(-d)` and fisk's `cdf` is flawless at 1.0 ulp, so this is a
  defect of `mielke_gen._cdf` alone.
- `kappa4`'s `_get_support` (line 7365) returns a lower endpoint that is wrong
  by 1.63e-9 relative (7.4e6 ulp) at k = 1e-8, signed *downwards*, so
  `pdf`/`cdf` get evaluated outside the true support and return `nan`, and
  `ppf` returns the wrong endpoint. Independently confirmed. A wrong support
  endpoint affects every method of the distribution, so it is worth fixing even
  though only one distribution shows it.
- `kappa4`'s exact `h == 0` / `k == 0` `_lazyselect` dispatch is why the
  limiting branches do not help at h or k = 1e-8: the dispatch is correct, the
  *neighbourhood* of the limit is unhandled. A lesson for any
  branch-on-exact-zero design.
- `alpha` F2 is a cancellation specific to its parameterisation:
  `a - 1.0/x` near the mode for huge a (`cdf(1e-154, 1e154)` = 0.5 vs 1.0,
  `logpdf` = +708.28 vs -4.86e273). At a = 1e6 the same mechanism costs up to
  9e6 ulp but stays within the input conditioning. Extreme regime only.
- `anglit` F1 (`cdf(-np.pi/4)` = `sf(np.pi/4)` = 0.0 vs 9.37e-34) comes from
  the support endpoint `np.pi/4` lying 3.06e-17 *inside* the true pi/4, so the
  public methods' boundary check returns 0 at a point with nonzero mass. It is
  related to `kappa4`'s endpoint problem in kind (a rounded support endpoint)
  but is harmless in practice: one point per tail, mass 1e-33. **Update
  2026-10-28: no longer single-distribution.** `cosine` F2 (verified) is the
  same mechanism: `cdf(-np.pi)` = `sf(np.pi)` = 0.0 vs 4.87e-50, while
  `cosine._cdf(-np.pi)` itself is correct. The 0 comes from the generic
  `rv_continuous` `_open_support_mask` (`_distn_infrastructure.py` lines 2164,
  2247), so it applies to every distribution whose support bound is a rounded
  constant. Low priority (cond 7.7e16), but a single fix in the infrastructure
  covers all of them.
- `cosine` F1 (`1 + np.cos(x)` cancels near x = +-pi; pdf is 0 and logpdf
  -inf for pi - |x| < 1.5e-8, up to 6e13 ulp before that) is specific to
  cosine. Maintainers acknowledged it in the merged test-only PR #18382, but
  it was never fixed. `cos(x/2)**2/pi` measured <= 1.35 ulp on the full grid.
- `betaprime` F4 (moderate): `x = r/(1 - r)` with `r = beta.ppf(q)` just
  below the r = 0.9999 switch (introduced by PR #17909 for #17631) amplifies
  the 0.19-ulp rounding of r by about x, up to 1.9e3 ulp. Using
  `betainccinv` for `1 - r` over a wider range removes it.

**12. `log(-log q)` returns exactly 0 at the double nearest the median-like
