## Cross-cutting issues

**1. The tail is built by subtraction instead of a complementary form - 7 of
8 distributions, plus a milder form in the eighth (`arcsine`).** This is the most consistent result of the review, and
the cheapest to fix: every distribution reviewed either implements `sf`/`logsf`
subtractively or inherits the generic versions, and in every case they collapse
in the right tail where a closed form exists.
- `fisk` F1: `_sf`/`_logsf` are `log1p(-cdf)`-shaped with `cdf -> 1`, so `sf`
  returns exactly `0.0` and `logsf` `-inf` for all `x > exp(36.7/c)`, with up
  to 5.0e14 ulp just before the cliff - although `sf = 1/(1 + x^c)` is exact.
- `mielke`: all four of `sf`, `logsf`, `logcdf`, `isf` are inherited and each
  fails at its demonstration point.
- `kappa4`: `sf(40, 0, 0) = 0.0` vs 4.25e-18, `logsf = -inf` vs -40,
  `isf(1e-300, 0, 0) = inf` vs 690.78.
- `gamma`: `logcdf`/`logsf` are not implemented at all; the generic
  `log(cdf)` / `log(sf)` underflows to `-inf` where the true log-probability is
  an ordinary number.
- `alpha`: `sf`, `logsf`, `logcdf`, `isf` are all inherited and all fail:
  `sf(1e17, 3.57) = 0.0` vs 6.8e-21, `logsf = -inf` vs -46.4,
  `logcdf(0.01, 3.57) = -inf` vs -4654.8, and `isf(1e-20, 3.57)` returns a
  *negative* number (-1.6e13 vs 6.8e16), because `ppf(1 - q)` takes the
  reciprocal of a rounding error.
- `anglit`: implements `sf` correctly but inherits `isf = ppf(1 - q)`:
  `isf(1e-18)` is off by 5.7e6 ulp, while `pi/4 - arcsin(sqrt(q))` is exact.
- `beta`: implements `sf`/`isf` properly (`betaincc`/`betainccinv`) but
  inherits `logcdf`/`logsf`, which underflow to `-inf` exactly as in `gamma`:
  `logcdf(1e-200, 3, 2) = -inf` vs -1380.16, `logsf(0.9, 1000, 1000) = -inf`
  vs -1026.15. A log-space `ibeta` prefix (`a log x + b log1p(-x) - betaln`)
  fixes both.
- `arcsine` (milder): inherited `sf = 1 - cdf` reaches 1.9e15 ulp at
  x = 1 - 1.1e-16. The tool rates it within conditioning (the input rounding
  of x near 1), but `2/pi*arcsin(sqrt(1 - x))` gives < 1 ulp for exact inputs.
SciPy tracks the pattern generically in #17832 (open) and #11465 (closed via
PR #21050) without having fixed it for any of these. One
`_sf`/`_logsf`/`_logcdf`/`_isf` override per distribution removes the class,
and the reports give closed forms under "Opportunities".

**2. An intermediate is formed explicitly and overflows, although the result is
a representable double - 5 of 8.** The same bug written five different ways
(`beta` F2 is the fifth: Boost `ibeta_derivative` overflows on
`1/(x*(1-x))` for x <~ 1e-308, and SciPy turns that into a Python
`OverflowError` - `beta.pdf` *raises* where the true pdf is 1.2e155; see 8):
- `alpha` F1, via the **shared helper `_norm_logpdf`** (`-x**2 / 2.0`,
  `_continuous_distns.py` line 367): `x**2` overflows for
  1.34e154 < |x| < 1.9e154, where `-x**2/2` is still finite, so
  `alpha.logpdf` returns `-inf` for x in about [5.3e-155, 7.5e-155] at any a.
  The helper is called 8 times in `_continuous_distns.py`; `norm.logpdf(1.5e154)`
  returns `-inf` where the truth is -1.125e308 (computed by hand, not run
  through the harness). `-(x/2)*x` or `-0.5*x*x` ordering avoids it.
- `fisk` F2/F3: `x**(-c-1)`, `x**(-c)` overflow for `x < exp(-709.8/(c+1))`, so
  `pdf` returns `nan`/`inf` and `logpdf`/`logcdf` `-inf`
  (`pdf(1e-300, 2)` = `nan`, truth 2e-300).
- `mielke` F1/F2/F3: the mirror image - `x**k` and `(1+x**s)**(1+k/s)` overflow
  in the *right* tail, so `cdf(1e10, 1e6, 1.0)` = `nan` (truth 0.9999) and
  `cdf(2.0, 1000, 1.0)` = `0.0` (truth 8.1e-177).
- `kappa4` F1/F5: `y = (1 - k x)**(1/k)` (or `exp(-x)` at k = 0) overflows for
  h < 0, and `q**h` for `|h| >~ 1e3`; `cdf(-700, -1e6, 0)` = `0.0` where the
  truth is 0.9993 at a conditioning of 7.0e-4 - a well-conditioned point in the
  *bulk* returning a completely wrong value, not a tail artefact.
Forming the expression in logs fixes all of them.

**3. `1 - u` cancellation inside `ppf`, driving the result to `inf`, `0` or
`nan` - 3 of 8.** `mielke` F4/F5 (`1 - q**(s/k)` -> 0 gives `inf` near q=1,
4.5e14 ulp before the cliff; `q**(s/k)` underflows to 0 for small q),
`kappa4` F3/F4 (`1 - q**h` and `1 - y**k` collapse; 1.2e22 ulp at
`|k| <~ 1e-4` - the largest single error in the review), and the `sf` side of
`fisk` F1. `expm1`/`log1p` formulations avoid it.

**4. A rounded exponent amplified by a large logarithm - 5 of 8** (`beta` F9:
Boost forms `x**a` as `exp(a log x)`, 756 ulp in the far left tail), though
always at the bottom of the severity scale (hundreds to a few thousand ulp):
`fisk` F5/F6 (`-c-1.0`, `-1.0/c`), `mielke` F8/F9 (`1/s`, `k/s` - the latter
can push `cdf` above 1), `kappa4` F8 (`1.0/k`, `1.0/h`), `gamma` F5
(`exp(exponent/a)` for a << 1). Real but far below the fixes above.

**5. Large terms cancelling in `logpdf` (and `pdf = exp(logpdf)` turning the
absolute error into a relative one) - 3 of 8.** `beta` F4 is the same
mechanism as `gamma` F2/F4: `xlogy + xlog1py - betaln` cancel terms of size
~a to an O(1) result (2.4e6 ulp at large shapes), made worse by `betaln`
itself (see 8).
`gamma` F2 is the severe instance (6.3e6 ulp at a=1e6: `_logpdf` cancels three
terms of size `a log a`, and exponentiating multiplies the surviving absolute
error by one); `kappa4` inherits the same amplification through
`_pdf = exp(_logpdf)`. It is a property of the idiom, not of either
distribution, so it is worth checking wherever it appears.

**6. Elementary `scipy.special` functions are sound; the incomplete gamma and
beta families are not.** In `fisk`, `mielke`, `kappa4` and `alpha` (`ndtr`,
`ndtri`) no special-function inaccuracy was found at all: `log1p`, `xlogy`,
`xlog1py` and `expm1` return correct values for the arguments they are given
- the arguments, and the absence of complementary forms, are the problem. The
exceptions are the incomplete gamma functions (7) and the Boost-backed
incomplete beta functions plus `betaln` (8):

**7. `scipy.special.gammainc` returns an unconverged result (the most valuable
single fix in the review).** It hands back the 2000-term partial sum of the
cephes `igam_series` Kummer series in the band just outside the Temme window
(`|x - a| > 4.5*sqrt(a)`), where up to 3e5 terms are needed. The verifier
reproduced SciPy's output *as* that partial sum to 1.6e-15 relative at four
independent points, so the mechanism is established rather than inferred, and
the branch edge is sharp (11.5 ulp at `4.49*sqrt(a)` vs. 38% relative error at
`4.51*sqrt(a)`, a=1e8). Relative error at `x = a - 5*sqrt(a)`: 4.3e-6 (a=1e6),
3.1e-2 (1e7), 0.347 (1e8), 0.719 (1e9).
- Affected here: `gamma` F1 (`cdf`, `sf`; 1.7e15 ulp) and F3 (`ppf`, `isf`, via
  `gammaincinv`/`gammainccinv` inverting the wrong cdf).
- Affected but unreviewed, via the same cephes code: `erlang` (a subclass of
  `gamma_gen` - literally the same lines), `dgamma`, `invgamma`, `gengamma`,
  `chi`/`chi2` (`chdtr`/`chdtrc`, df >~ 4e5), and the Poisson cdf (`pdtr` is
  `igamc`). (The negative-binomial cdf uses the incomplete *beta* function,
  see 8, not `igamc`.)
- Not reported on SciPy's tracker. The same *class* of unconverged-iterate bug
  has been filed against downstream reimplementations (jax-ml/jax #41201, where
  SciPy is cited as the correct reference), which is further reason to report
  it upstream rather than assume it is known.

**8. The Boost incomplete-beta family: `ibeta_inv` gives up, `ibeta_derivative`
raises, and `betaln` loses digits (from `beta`, all verified).** Three
separate defects, all below `scipy.stats`:
- **`ibeta_inv` (`scu._beta_ppf`, `sc.betaincinv`, `sc.betainccinv`)** hits
  its root-finding iteration cap and returns the last iterate or `nan` (with a
  "Root finding evaluation exceeded ... iterations" RuntimeWarning): `beta`
  F1 (`ppf` returns 0.5 where the truth is 2.8e-33, `nan`, or 6.6e-53 vs
  1.4e-156, in irregular bands of small q, e.g. `ppf(1e-9, 0.5, 2)`), F3
  (`isf` returns `nan` instead of 1.0 for b = 2, q <~ 1e-186), F5 (8.5e6 ulp
  near DBL_MIN) and the moderate F6/F7. The same class of bug as 7 (an
  iterate returned as if converged), here at least with a warning. Callers:
  `betaprime`, `rdist`, `jf_skew_t` and every direct user of
  `betaincinv`/`betainccinv`. Related upstream: boostorg/math #1511 (another
  `ibeta_inv` failure, fixed in Boost Oct 2026); SciPy #12796 (an earlier
  `betaincinv` failure, fixed in 1.12.0).
- **`ibeta_derivative` (`scu._beta_pdf`)** raises Python `OverflowError`
  instead of returning a value for x <~ 1e-308 (`beta` F2) - the only
  *exception* (rather than a wrong number) in the review. `accuracy.py` itself
  aborts on it. Affects every caller of `beta._pdf`.
- **`sc.betaln`** (cephes `lbeta`) is off by up to 6.9e5 ulp when a >> b but
  a < 1e6*b (4e4 ulp at (1e6, 2)); the asymptotic branch beyond a > 1e6*b is
  fine. Drives `beta` F4 and also enters the logpdf of `betaprime`, `f` and
  `rdist`.
- Affected but unreviewed: `betaprime`, `rdist`, `f`, `jf_skew_t`, and the
  discrete `nbinom`/`binom` cdfs and quantiles (incomplete beta).

**Two defects that are NOT cross-cutting, and should not be mistaken for it:**
- `mielke` F1 (the `cdf` collapse) has **no** burr/fisk counterpart. The
  verifier confirmed `burr_gen._cdf` (line 1218) already uses the bounded
  `(1 + x**-c)**(-d)` and fisk's `cdf` is flawless at 1.0 ulp, so this is a
  defect of `mielke_gen._cdf` alone.
- `kappa4`'s `_get_support` (line 7365) returns a lower endpoint that is wrong
  by 1.63e-9 relative (7.4e6 ulp) at k = 1e-8, signed *downwards*, so
  `pdf`/`cdf` get evaluated outside the true support and return `nan`, and
  `ppf` returns the wrong endpoint. Independently confirmed. A wrong support
  endpoint affects every method of the distribution, so it is worth fixing even
  though only one distribution shows it.
- `kappa4`'s exact `h == 0` / `k == 0` `_lazyselect` dispatch is why the
  limiting branches do not help at h or k = 1e-8: the dispatch is correct, the
  *neighbourhood* of the limit is unhandled. A lesson for any
  branch-on-exact-zero design.
- `alpha` F2 is a cancellation specific to its parameterisation:
  `a - 1.0/x` near the mode for huge a (`cdf(1e-154, 1e154)` = 0.5 vs 1.0,
  `logpdf` = +708.28 vs -4.86e273). At a = 1e6 the same mechanism costs up to
  9e6 ulp but stays within the input conditioning. Extreme regime only.
- `anglit` F1 (`cdf(-np.pi/4)` = `sf(np.pi/4)` = 0.0 vs 9.37e-34) comes from
  the support endpoint `np.pi/4` lying 3.06e-17 *inside* the true pi/4, so the
  public methods' boundary check returns 0 at a point with nonzero mass. It is
  related to `kappa4`'s endpoint problem in kind (a rounded support endpoint)
  but is harmless in practice: one point per tail, mass 1e-33.

## Notes

- **`kappa4` is tagged "(light)" in the table above by mistake.** It was a full
  measured review (13 parameter sets covering every `_lazyselect` branch). The
  tag comes from the checker's heuristic in
  `.claude/skills/dist-accuracy-orchestrate/scripts/reports.py:67`, which greps
  the Findings section for the string "not measured"; kappa4's F1 legitimately
  says one sub-regime (k < 0 with `|k| >~ 0.05`) is unreachable in double
  precision. The heuristic gives a false positive on any report that documents
  an unreachable regime. Not worked around in the report.
- **burr and burr12 remain unreviewed**, and `burr_gen` is where all four of
  fisk's loss findings actually live (`fisk_gen` only forwards `d = 1.0`), so
  `fisk.md` cites the burr review bundled with the skill
  (`.claude/skills/dist-accuracy-review/references/burr-example.md`, same SciPy
  version). A fix in `burr_gen._pdf/_logpdf/_logcdf/_sf/_logsf` repairs burr and
  fisk at once. `mielke` was reviewed in its own right and shares no literal
  code with them.
- **Two severities rest on inspection rather than on the harness.** `mielke`
  F10 (`logpdf(0, 1, s)` = `nan` where the exact value is 0.0) is scored `loss`
  by inspection: x = 0 is outside the grid and 0.0 is not a normal double, so
  it carries no ulp figure. The verifier confirmed the values and agreed the
  severity is justified in spirit while noting it falls outside the tool's
  literal definition. `kappa4` F7's token reads `loss` although the finding
  spans two regimes (systematically severe at 3.7e7 ulp, loss-level `nan` next
  to the lower endpoint); the checker rejects composite tokens, so the table
  shows the worse of the two.
- **Regimes that could not be measured.** `fisk`: x = 0 (the reference divides
  by zero - the `x == 0` branch was checked by reading the code), and F1 for
  `c <= 1e-3`. `mielke`: the (k, s) = (1e6, 1e-3) set has no measurable point
  at all (the true cdf is subnormal for every double x), and pattern 4
  (subnormal `x**(k-1)`) has no normal-double result so it is not scored.
  `kappa4`: F1 for k < 0 with `|k| >~ 0.05` is unreachable in double precision,
  and 16 grid points sitting exactly on support endpoints have no reference.
  `gamma`: mpmath's `gammainc` does not converge for `a >= 1e7`, so a = 1e8
  needed a series-based reference (the verifier built two independent routes -
  high-precision quadrature of the pdf and the fully converged Kummer series,
  agreeing to 42 digits) and `a >= 1e10` could not be measured, so the trend
  there is extrapolated.
- **One `gamma` regime claim is narrower than reality** (recorded in that
  report's Verification section; no number corrected): F1's stated upper edge
  `a - x <~ 15*sqrt(a)` holds at a=1e6, but the window widens with `a` - at
  a=1e8 the relative error is still 4.8e-2 at `15*sqrt(a)` and 2.4e-3 at
  `30*sqrt(a)`.
- **MAXITER=2000 was confirmed behaviourally, not by reading C.** The cephes
  sources are not shipped in this install, so the attribution rests on
  reproducing SciPy's return value as the exact 2000-term partial sum. All
  Python-side line citations were checked against the installed source.
- **Three reports were corrected after verification**, none in its numbers
  except where stated: `fisk` (F2 regime windows understated, F4's cancelling
  constant and range, burr line numbers off by 3-4), `mielke` (the fisk
  correspondence was overstated - see above), `kappa4` (F1's regime restated in
  terms of `log|h| + ly > 709.78` rather than a fixed x; one F6 `nan`
  reproducer re-attributed to F7; `_logpdf`/`_ppf` line numbers). `mielke` also
  needed one format fix (F10 initially carried the severity "not scored",
  which the checker rejects).
- **`alpha`** (run 2026-10-21): ppf at a = 1e154 could not be measured (the
  reference inversion is unavailable there). `pdf` returns `nan` instead of 0
  for x < 7.5e-155 (`inf*0`); the true value underflows, so it is recorded
  under RuntimeWarnings, not as a finding. The verifier noted one wording
  error in F2: the `logpdf(1e-154, 1e154)` error is about 4.5e15 ulp (finite,
  wrong sign), not "inf" ulp; the severity (loss) is unaffected and the report
  was left as is.
- **`anglit`**: the inventory lists inherited `logcdf`/`logsf` as plain
  `log(cdf)`/`log(sf)`, but in SciPy 1.18.1 the `rv_continuous` default
  switches at the median to `log1p(-sf)`/`log1p(-cdf)`; the analyst measured

  is out of date. The inherited `logpdf = log(cos 2x)` returns 0 for
  |x| < ~1e-8 (loss-level, listed as an opportunity: `log1p(-2*sin(x)**2)`).
- **`arcsine`** (run 2026-10-21): 0 findings, so no verification ran
  ("pending" in the table is expected). Only the three implemented methods

- **Tooling limitations.** The `--plot` option of the skill's `accuracy.py`
